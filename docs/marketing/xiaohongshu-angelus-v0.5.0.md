## 正文（最终版，可直接发布）

多 Agent 跑 40 分钟，进程一崩全白干？😭

这不是段子，是我这个月真实踩的坑。
跑一个 swarm 任务，coordinator + 5 个 worker 各司其职，眼看着进度到 80%，服务一崩，全部回到第 0 步。重来？重新喂上下文、重新建 worker、重新等 40 分钟。

直到我换了个本地多 Agent 控制台——**Angelus v0.5.0**。

它解决的不是"让 Agent 跑起来"，而是：
**"Agent 跑偏、崩了以后，你能做什么？"**

🛰️ **看见每一只 Agent**
所有 worker 在线一览：谁在跑、做到哪一步、烧了多少 token，拓扑和任务流转全可视化。黑盒？不存在的。

🔧 **运行中可干预**
不用停整个团队！单点暂停、注入方向、steer 修正，改完继续跑，兄弟 worker 全程无感。跑偏当场拽回来。

💾 **上下文可编辑、可回滚**
每个 Agent 的私有上下文都能打开、版本化编辑、一键回滚，还带审计记录（谁改的、为什么改）。手贱改坏了？一秒还原。

🧠 **组织级恢复**
整个 Agent 组织（拓扑 + worker + 任务）被当作运行时状态持久化。进程挂了、电脑重启了，打开同一会话，组织还在，接着干活。

一句话总结：
> 不只是让 Agent 跑起来，而是让整个 Agent 组织可以被看见、被干预、被恢复。

Control your agents, not just prompt them. 🎯
